# VPN-сервис — план и состояние работ

Коротко: продаём доступ к VPN, а не приложение. Пользователь платит на сайте,
получает персональную подписочную ссылку и импортирует её в один тап в
сторонний open-source клиент. Своего приложения не делаем.

## Почему именно так

Сайт физически не может включить VPN на устройстве — ни iOS, ни Android, ни
десктоп не дают браузеру доступ к сетевому стеку. Клиентское приложение нужно
всегда, у любого VPN-сервиса без исключений. Своё приложение на iOS упирается в
App Store, откуда Apple с 2024 года по требованию РКН вычищает VPN-приложения.
Поэтому используем чужие универсальные клиенты, а всю ценность держим в сервисе:
скорость подключения, простота онбординга, поддержка.

## Архитектура

```
Пользователь → сайт (оплата) → API панели → персональная подписочная ссылка
                                                      │
                        экран /setup: кнопки под платформу + deep-link
                                                      │
                        сторонний клиент импортирует подписку → тумблер «вкл»
```

| Слой | Решение |
|---|---|
| Протокол | VLESS + Reality, flow `xtls-rprx-vision` |
| Ядро | Xray-core на VPS за границей |
| Панель | Remnawave — REST API, мультинода, подписки, аналитика |
| Сайт | Next.js 16 + TypeScript + Tailwind 4 |
| База | Управляемая PostgreSQL на Timeweb (`DATABASE_URL`); без неё — память процесса |
| Клиенты | Только INCY — есть под iOS, Android, Windows, macOS, Linux и ТВ (решение 06.09.2026) |
| Оплата | Т-Касса (интернет-эквайринг Т-Бизнеса), сценарий non-PCI: платёжная форма банка |

Продуктовые решения зафиксированы в `vpn_product_assembly_prompt.md`
(блок «Зафиксированные решения»): 1 аккаунт = 1 подписка (на все устройства пользователя),
тариф 250/1350/2400 ₽, триал 3 дня с лимитом трафика, автопродление галочкой,
грейс-период сутки, без рефералки.

## Запуск локально

```bash
cd web
npm install
npm run dev
```

Сайт поднимется на http://localhost:3000. Панель работает в мок-режиме, пока не
заданы переменные окружения:

```
PANEL_URL=https://panel.example.com
PANEL_TOKEN=...
PANEL_SQUAD_UUID=...
SUBSCRIPTION_HOST=https://sub.example.com
```

Все переменные окружения сайта:

| Переменная | Зачем |
|---|---|
| `DATABASE_URL`, `DATABASE_SSL_CA` | PostgreSQL Timeweb и её корневой сертификат (PEM) |
| `PANEL_URL`, `PANEL_TOKEN`, `PANEL_SQUAD_UUID` | панель Remnawave (`PANEL_URL` — только HTTPS-адрес через Caddy, см. ниже); без них — мок |
| `SUBSCRIPTION_HOST` | домен подписочных ссылок |
| `SITE_URL` | публичный адрес сайта — для ссылок в письмах и боте |
| `ADMIN_CODE` | вход в `/admin` и ключ для `/api/cron` |
| `TRIAL_TRAFFIC_GB` | лимит трафика триала, по умолчанию 10 |
| `VPN_EXIT_IPS` | адреса нод через запятую — распознавать заход через наш VPN |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` | бот уведомлений |
| `TELEGRAM_API_BASE` | ретранслятор вместо `api.telegram.org` — с российского хостинга прямой доступ закрыт |
| `TBANK_TERMINAL_KEY`, `TBANK_PASSWORD` | Т-Касса; без них оплата не проводится и доступ выдаётся сразу (стенд) |
| `TBANK_API_URL` | по умолчанию `https://securepay.tbank.ru/v2`; старый `securepay.tinkoff.ru` мёртв по TLS |
| `PRICE_<ТАРИФ>_KOPECKS` | цена в копейках, если надо поменять без релиза (`PRICE_M6_KOPECKS=135000`) |
| `SMTP_URL`, `MAIL_FROM` | почта: `smtps://user:pass@host:465`; `SMTP_URL=log` печатает письма в консоль (разработка) |
| `REMINDERS_DISABLED=1` | выключить планировщик напоминаний (для тестов) |
| `COMPANY_NAME`, `COMPANY_OGRNIP`, `COMPANY_INN`, `COMPANY_EMAIL` | реквизиты ИП в подвале и в оферте (ст. 9 ЗоЗПП); без них подвал показывает предупреждение |
| `COMPANY_ADDRESS` | адрес регистрации — только в оферте, в подвале не показывается: для ИП это домашний адрес |
| `COMPANY_BANK_NAME`, `COMPANY_BANK_ACCOUNT`, `COMPANY_BANK_BIK`, `COMPANY_BANK_CORR`, `COMPANY_BANK_INN` | банковские реквизиты в разделе 17 оферты |
| `ANALYTICS_SALT` | секретная строка для обезличивания IP в статистике; менять нельзя — иначе старые и новые отпечатки перестанут совпадать |
| `EVENTS_RETENTION_DAYS` | сколько дней хранить статистику, по умолчанию 365 |

### IP сервера панели заблокирован в сети Timeweb

Проверено 06.09.2026: с серверов Timeweb до `95.182.85.234` не доходит ни один
пакет (tcpdump на самой Риге — ноль SYN), при этом из Германии, Финляндии,
Казахстана адрес открывается мгновенно, а из российских точек check-host.net —
две из трёх дают таймаут на любой порт, включая 22 и 443. Это блокировка
адреса на уровне ТСПУ у части операторов, и сеть Timeweb среди них. IPv6 на
сервере нет, обойти нечем.

🔴 Отдельно: с того же Timeweb недоступен и `api.telegram.org`. Вебхук
работает — его шлёт Telegram к нам, — а отправка сообщений ботом молча не
проходит.

**Решено ретрансляторами на Cloudflare Workers (06.09.2026).** `workers.dev`
с Timeweb доступен, до Риги и Telegram Cloudflare дотягивается. Развёрнуто два
воркера, оба — простые форвардеры без секретов:

| Воркер | Куда ведёт | Переменная-переопределение |
|---|---|---|
| `irek-panel-proxy.nikitasoin.workers.dev` | `95-182-85-234.sslip.io:8443` (панель) | `PANEL_PROXY_URL` |
| `irek-telegram-proxy.nikitasoin.workers.dev` | `api.telegram.org` | `TELEGRAM_API_BASE` |

**Переменные править не нужно.** Адреса воркеров зашиты в код
(`panel.ts`, `telegram.ts`) — они не секрет. Ходим через ретранслятор
**сразу**: прямой путь с Timeweb заведомо мёртв, и пробовать его первым
значило бы платить таймаут на каждом старте процесса. Прямой адрес остаётся
запасным на случай, если Cloudflare недоступен; сработавший адрес
запоминается. Ошибки самой панели (4xx/5xx) переключением не считаются.
Отключить ретранслятор — задать `PANEL_PROXY_URL=off` / `TELEGRAM_API_BASE=off`.

Замер включения пробного периода при мёртвом прямом адресе: было 6.7 с,
стало 1.4 с.

Порт 8443, а не 3000: Workers ходят только на стандартные порты. Исходники —
`~/irek-panel-proxy/` и `~/irek-telegram-proxy/`, деплой `npx wrangler deploy`.
Подписочная ссылка клиента тоже собирается от `PANEL_URL`, то есть идёт через
Cloudflare и обновляется даже там, где прямой адрес Риги недоступен.

Что осталось несделанным: сам VPN-трафик идёт на `95.182.85.234:443` напрямую,
ретранслировать его нельзя. Если адрес недоступен у оператора клиента, VPN у
него не заработает — лечится только сменой IP ноды.

Два следствия (актуальны, только если ретрансляторы отключить):

1. Сайт не может выдать доступ сам. Временный мост — `web/scripts/provision.mjs`:
   запускается с ноутбука (оттуда панель доступна), заводит доступ тем
   аккаунтам, кому сайт не смог, и пишет `panel_token` в базу.
2. **Клиенты на тех же операторах не подключатся и к самому VPN** — Reality
   слушает 443 на том же адресе. Это блокер запуска, а не неудобство.

Лечится сменой IP сервера панели/ноды у хостера (`Cloud Software FZCO`, LV),
либо переносом панели за домен на Cloudflare (тогда чинится только пункт 1).
Правильная архитектура — панель и ноды на разных адресах: блокировка ноды не
должна ронять управление.

### Панель за HTTPS (Caddy на сервере панели)

Панель Remnawave пускает API-запросы только с заголовками `X-Forwarded-Proto:
https` и `X-Forwarded-For`. Исходящий прокси Timeweb переписывает
`X-Forwarded-Proto` на `http`, если сайт ходит в панель по обычному HTTP, —
панель рвёт соединение, создание аккаунта падает. Поэтому на сервере панели
стоит Caddy: `https://95-182-85-234.sslip.io:3000` (запасной `:8443`) →
`127.0.0.1:3000`, сертификат Let's Encrypt (HTTP-01 через :80; :443 занят
Xray Reality). Порт 3000 выбран потому, что исходящие соединения с Timeweb
на 8443 не проходят, а на 3000 проходят (проверено `/api/diag`, поле
`panelNet.ports`). Панель в docker-compose привязана к `127.0.0.1:3000`,
Caddy — к внешнему IP. `PANEL_URL` указывает на HTTPS-адрес. Дашборд панели по нему открывается в
браузере. Конфиг — `/etc/caddy/Caddyfile` на сервере. Когда появится домен,
заменить `sslip.io`-имя на свой поддомен панели.

### Почему Telegram через Bot API, а не через переданный воркер

Передан пакет `irek-telegram-handoff` (лежит вне репозитория,
`~/irek-private/`): Python + Playwright, который открывает Telegram Web под
обычным аккаунтом и вручную «печатает» сообщения. В этот проект он не
встроен, потому что:

1. Ему нужен Chromium и отдельный постоянно живущий процесс с профилем на
   диске. Контейнер Timeweb пересобирается при каждом пуше и ничего на диске
   не хранит — воркеру пришлось бы жить на отдельном сервере.
2. Отправка с личного аккаунта автоматизацией — прямое нарушение правил
   Telegram, аккаунт могут заблокировать вместе с историей переписки.
3. Он требует от пользователя ввести свой username и доверить его нам, а
   бот привязывается одним тапом по ссылке и сам знает, кому писать.

Bot API делает то же самое штатно, бесплатно и в 60 строк кода. Шаблоны
текстов из воркера можно перенести в `web/src/lib/notify.ts`.

## Открытые риски

1. **Блокировки.** РКН учится детектировать Reality. Нужен запас серверов и
   готовность быстро менять IP.
2. **Приём платежей.** Отказ эквайера — самый вероятный блокер запуска.
3. **Доступность клиентов.** Состав приложений в App Store меняется помесячно,
   поэтому на `/setup` всегда несколько вариантов и ручной способ импорта.
4. **Правовое поле.** Закон 149-ФЗ обязывает VPN-сервисы подключаться к реестру
   РКН. Требует отдельного решения до публичного запуска.
