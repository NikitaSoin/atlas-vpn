# VPN-сервис — план и состояние работ

Коротко: продаём доступ к VPN, а не приложение. Пользователь платит на сайте,
получает персональную подписочную ссылку и импортирует её в один тап в
сторонний open-source клиент. Своего приложения не делаем.

## Почему именно так

Сайт физически не может включить VPN на устройстве — ни iOS, ни Android, ни
десктоп не дают браузеру доступ к сетевому стеку. Клиентское приложение нужно
всегда, у любого VPN-сервиса без исключений. Своё приложение на iOS упирается в
App Store, откуда Apple с 2024 года по требованию РКН вычищает VPN-приложения.
Поэтому используем чужие универсальные клиенты, а всю ценность держим в сервисе:
скорость подключения, простота онбординга, поддержка.

## Архитектура

```
Пользователь → сайт (оплата) → API панели → персональная подписочная ссылка
                                                      │
                        экран /setup: кнопки под платформу + deep-link
                                                      │
                        сторонний клиент импортирует подписку → тумблер «вкл»
```

| Слой | Решение |
|---|---|
| Протокол | VLESS + Reality, flow `xtls-rprx-vision` |
| Ядро | Xray-core на VPS за границей |
| Панель | Remnawave — REST API, мультинода, подписки, аналитика |
| Сайт | Next.js 16 + TypeScript + Tailwind 4 |
| База | Управляемая PostgreSQL на Timeweb (`DATABASE_URL`); без неё — память процесса |
| Клиенты | INCY (iOS, основной), v2rayNG / Happ (Android), Clash Verge Rev (десктоп) |
| Оплата | Т-Касса (интернет-эквайринг Т-Бизнеса) — в процессе подключения |

Продуктовые решения зафиксированы в `vpn_product_assembly_prompt.md`
(блок «Зафиксированные решения»): 1 аккаунт = 1 подписка = 1 устройство,
тариф 250/1350/2400 ₽, триал 3 дня с лимитом трафика, автопродление галочкой,
грейс-период сутки, без рефералки.

## Запуск локально

```bash
cd web
npm install
npm run dev
```

Сайт поднимется на http://localhost:3000. Панель работает в мок-режиме, пока не
заданы переменные окружения:

```
PANEL_URL=https://panel.example.com
PANEL_TOKEN=...
PANEL_SQUAD_UUID=...
SUBSCRIPTION_HOST=https://sub.example.com
```

Все переменные окружения сайта:

| Переменная | Зачем |
|---|---|
| `DATABASE_URL`, `DATABASE_SSL_CA` | PostgreSQL Timeweb и её корневой сертификат (PEM) |
| `PANEL_URL`, `PANEL_TOKEN`, `PANEL_SQUAD_UUID` | панель Remnawave; без них — мок |
| `SUBSCRIPTION_HOST` | домен подписочных ссылок |
| `SITE_URL` | публичный адрес сайта — для ссылок в письмах и боте |
| `ADMIN_CODE` | вход в `/admin` и ключ для `/api/cron` |
| `TRIAL_TRAFFIC_GB` | лимит трафика триала, по умолчанию 10 |
| `VPN_EXIT_IPS` | адреса нод через запятую — распознавать заход через наш VPN |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`, `TELEGRAM_WEBHOOK_SECRET` | бот уведомлений |
| `SMTP_URL`, `MAIL_FROM` | почта: `smtps://user:pass@host:465` |
| `REMINDERS_DISABLED=1` | выключить планировщик напоминаний (для тестов) |

### Почему Telegram через Bot API, а не через переданный воркер

Передан пакет `irek-telegram-handoff` (лежит вне репозитория,
`~/irek-private/`): Python + Playwright, который открывает Telegram Web под
обычным аккаунтом и вручную «печатает» сообщения. В этот проект он не
встроен, потому что:

1. Ему нужен Chromium и отдельный постоянно живущий процесс с профилем на
   диске. Контейнер Timeweb пересобирается при каждом пуше и ничего на диске
   не хранит — воркеру пришлось бы жить на отдельном сервере.
2. Отправка с личного аккаунта автоматизацией — прямое нарушение правил
   Telegram, аккаунт могут заблокировать вместе с историей переписки.
3. Он требует от пользователя ввести свой username и доверить его нам, а
   бот привязывается одним тапом по ссылке и сам знает, кому писать.

Bot API делает то же самое штатно, бесплатно и в 60 строк кода. Шаблоны
текстов из воркера можно перенести в `web/src/lib/notify.ts`.

## Открытые риски

1. **Блокировки.** РКН учится детектировать Reality. Нужен запас серверов и
   готовность быстро менять IP.
2. **Приём платежей.** Отказ эквайера — самый вероятный блокер запуска.
3. **Доступность клиентов.** Состав приложений в App Store меняется помесячно,
   поэтому на `/setup` всегда несколько вариантов и ручной способ импорта.
4. **Правовое поле.** Закон 149-ФЗ обязывает VPN-сервисы подключаться к реестру
   РКН. Требует отдельного решения до публичного запуска.
